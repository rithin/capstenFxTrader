# API & recorder conventions

## Layout (`services/api/app/`)
- `routes/<resource>.py`: thin routers only. `services/<resource>.py`: logic. `db/models.py`: SQLAlchemy 2 models.
- `schemas/`: request/response Pydantic models. Event and command payloads come from `packages/contracts`. Never redefine them.
- `migrations/`: Alembic. One migration per PR, autogenerated, then reviewed by hand.

## Rules
- Async everywhere (`asyncpg`, `redis.asyncio`). Dependency-inject the DB session and the Redis client.
- Every route has an explicit `response_model` and `tags`, because the UI client is generated from OpenAPI.
- Command routes: validate → write `audit_log` → XADD to `commands.node` → wait for an ack with a timeout → return the status.
- Never return secrets. Broker endpoints return a secret *reference name* only.
- Recorder: consumer groups, idempotent upserts keyed by Nautilus IDs, ack only after commit.

## After changing the API surface
1. If the change touches `docs/ARCHITECTURE.md` §5, it's a contract change: use `/contract-change`.
2. Regenerate the UI client: `make api-client` (runs `openapi-typescript` against `/openapi.json` →
   `apps/web/src/lib/api/schema.d.ts`) and commit it with the change.

## Tests
`pytest` + `httpx.AsyncClient`. Postgres and Redis come from testcontainers or the k3d stack (`make test m=api`).
